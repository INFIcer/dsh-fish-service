# P2：DSH 界面入口（朗读按钮 + 语音输入）

> 状态：**已完成**（2026-11-09）。
> 依赖：P1 的 `fish.service` / 宿主路由 / 设置页；不依赖 P3（WebUI 内嵌、安装器）。
> 平台：DSH `0.2.2-rc.1` Web；纯原生 JS + React（平台自带），无 npm / CDN / 构建。

---

## 1. 范围

P2 只做「界面入口」：

1. 每条**已定稿**助手消息旁一个朗读按钮（消息操作行）；
2. 输入框旁一个麦克风按钮：录音 → **转文字 / 保留语音 / 取消** 三选一；
3. 输入框左侧「自动朗读」开关（默认关）；
4. 设置页在 P1 同一页里补「朗读」「语音输入」两个分区；
5. 宿主新增 4 条路由：`/read`、`/audio`、`/transcribe-upload`、`/voice-upload`。

> 性能修复追加（2026-11-09）：`/read` 批间并发、TTS 缓存真正生效、流式朗读
> `/read/plan` + `/read/segment`、`/cache/*` 运维路由。细节见
> [`docs/TTS_CACHE.md`](TTS_CACHE.md)；本文第 3、5、7、8 节已同步更新。

**不做**：内嵌 WebUI / 一键安装（P3）、`fish-ops`（P4）、云端 ASR/TTS、跨会话播放队列。

## 2. 客户端挂载点（实测依据）

槽位契约来自 DSH 0.2.2 客户端 bundle 的 Slots 契约表（`Slots.listSubTree` 的同一份数据）：

| 槽位 | 类型 | 我们注册的 id / order | 说明 |
| --- | --- | --- | --- |
| `conversation.chat.assistant-actions` | list / session | `fish-read` / 21 | 已定稿助手消息的图标操作行；owner props = `{ messageId }`，标准 props 另带 `useChat` / `sessionId` / `inputActions` 等 |
| `conversation.input.right` | list / session | `fish-mic` / 32 | 输入框发送按钮前的工具区 |
| `conversation.input.overlay` | list / session | `fish-voice` / 40 | 输入框卡片内的浮层（浮层必须挂这里；绝对定位以卡片为参照） |
| `conversation.input.left` | list / session | `fish-auto-read` / 45 | 输入框左侧（与内置语音输入的实验槽位同区） |
| `settings.section` | list | `fish-service` / 57 | 设置页「本地 AI」tab（P1 已有，P2 加分区的） |

关键 API（全部来自标准 props，不猜、不读别人的 DOM）：

- `useChat(selector)`：读 Chat 快照。我们用
  `snapshot.timeline.turnOrder` → `snapshot.locations.getTurn(turn)` → `snapshot.nodes.get(key)`，
  找到 `kind === 'turn-tail'` 且 `data.closing.finalNode.messageId === messageId` 的轮次，
  再读这个尾节点 `data.closing.blocks` 里的 `kind === 'text'` 块 —— 也就是这一轮的**最终回复**。
  **不读工具调用 / 思考 / 中间步骤**（代码块在宿主预处理里再处理一次）。
- `inputActions.captureInsertion()`：录音开始时记下「草稿选区 + 版本号」。
- `inputActions.insertText(text, span)`：只有版本没变、编辑器可编辑时才插入并返回 `true`；
  失败不能去改 DOM（会打乱 React/编辑器状态），我们保留文本并给「重试插入 / 复制文字」。
- `props.sessionId`：录音面板只服务开始录音的那个会话。

兼容兜底：

- `useChat` 取不到文字时，从按钮所在的 `[data-chat-flow-key]` 行往上找最近一条
  `data-chat-flow-kind="assistant-step"` 的 DOM 文本（只作为最后手段）。
- `slots` 服务在 DSH 启动早期可能还没就绪：注册失败会 250ms 重试，最多 40 次
  （与 `dsh-peak-scheduler` 相同的做法），不会让插件挂掉。

## 3. 朗读按钮

### 3.1 交互

| 状态 | 图标 | 点击行为 |
| --- | --- | --- |
| 空闲 | 喇叭 | 取消息文本 → `POST /read/plan` 拿分段 → 按顺序 `POST /read/segment`，第 1 段到了就播 |
| 合成中 | 转圈（`fish-spin`） | 停止（丢弃这次结果，并 abort 未完成的 segment 请求） |
| 播放中（这条） | 暂停 | 停止（暂停并清空队列） |
| 播放中（别的消息） | 喇叭 | 先停上一条，再流式朗读这条 |
| 失败 | 喇叭 + 行内红字 | 再点重试 |

- 播放在全局唯一一个「播放器」里：`Audio` 对象 + 代次号 + `AbortController`。
  切换消息、停止、组件卸载都不会留下继续响的音频，也不会留下还在跑的合成请求。
- 长文本：`/read/plan` 立即返回分段，客户端按顺序请求 `/read/segment`；
  拿到第 N 段就开始播，同时预取第 N+1 段（最多 2 个 segment 请求在飞）。
  同一段重复朗读由服务端缓存直接命中。
- 失败提示用人话（直接取宿主返回的 `hint`）：
  「本地 AI 服务没在运行」「显存不够…」「缺少 TTS 模型…」。

### 3.2 自动朗读

- 输入框左侧的开关，按会话保存到 `config.autoReadSessions[sessionId]`；
  当前会话没有单独设置时回落到 `config.autoRead`（设置页里的「新会话默认自动朗读」）。
- 切换开关只写当前会话这一条，不影响其它会话与全局默认；切换会话时按钮状态按会话重新取值。
- 开启后：仅当**这条消息比该会话首次看到的末轮更新、且是最后一轮**、页面可见、偏好已加载、
  且这条消息在本页没自动读过时才触发一次。打开旧会话不会把历史念一遍。
- 打开设置页里「新会话默认自动朗读」的瞬间**不会**回读历史（只有组件挂载时就已加载偏好才参与自动朗读）。

## 4. 语音输入

### 4.1 录音

- `navigator.mediaDevices.getUserMedia({audio:{channelCount:1, echoCancellation, noiseSuppression}})`。
- 格式（设置页可选 `auto / webm / wav`）：
  - `auto`（默认）：`MediaRecorder` 依次尝试 `audio/webm;codecs=opus`、
    `audio/webm`、`audio/ogg;codecs=opus`、`audio/mp4`；
  - `webm`：只试 opus/webm；
  - `wav`（或浏览器没有 `MediaRecorder`）：WebAudio `ScriptProcessor` 采 PCM，
    自己编码 16-bit 单声道 WAV。
- 录音中：麦克风按钮变红点 + `0:03` 计时；输入框上方浮层显示计时、电平波形、「停止并选择 / 取消录音」。
- 上限：**5 分钟**（到点自动停）、**25MB**；超限直接放弃并用人话提示。
- 关闭面板 / 切换会话 / 卸载输入框会取消正在进行的录音；「允许麦克风」弹窗还没点时取消，
  晚到的 `getUserMedia` 结果会被代号检查丢弃，不会偷偷开始录。

### 4.2 结束时三选一

浮层（`conversation.input.overlay`）里三个按钮：

1. **转文字**
   - `POST /transcribe-upload`（multipart：`file`、`durationMs`、`language`、`speaker=false`）；
   - 成功把文本插到**录音开始时**的光标处（`captureInsertion` → `insertText`）；
   - 显示「已转写 N 字（耗时 X ms）」；输入框拒绝插入（版本变了/不可编辑）时：
     再按当前光标试一次 → 仍失败则复制到剪贴板 + 面板里保留「重试插入 / 复制文字」。
2. **保留语音**
   - `POST /voice-upload` 把音频存到 `<cacheDir>/voice/<uuid>.<ext>`；
   - DSH 0.2.2 的输入框附件只接受上传回执 id（`inputActions.addAttachments(ids)`），
     插件没有公开接口把任意本地文件变成草稿附件，所以按任务书允许的降级：
     **把 `（语音附件：<绝对路径>）` 插到光标处**，并明确提示「这个版本不支持音频附件」；
   - 面板保留「补上文字（可选转写）」，点了就用同一段音频调 ASR 并把文字补进输入框。
3. **取消**：丢弃录音，什么都不插。

「记住上次选择」：只把上次的按钮**高亮**成默认（localStorage `dsh-fish-service.voice-choice`），
**不会自动执行**；设置页可以关掉这个记忆。

## 5. 宿主路由（新增）

前缀 `/dsh-fish-service`；`Origin` 存在时校验同源。

### 5.1 `POST /read`

请求：`{text, voice?, speed?, maxChars?, skipCodeBlocks?}`

- `text` 必填（消息原文，Markdown 未处理）；
- `voice` 默认 `config.ttsVoice`；`speed` 0.5~2.0，默认 `config.ttsSpeed`；
- `maxChars` 200~5000，默认 `config.readMaxChars`；
- `skipCodeBlocks` 默认 `config.readSkipCode`。

返回：

```json
{
  "ok": true,
  "wavPath": "C:\\Users\\…\\fish-service-cache\\tts\\a1b2-….wav",
  "ms": 2310,
  "items": [
    { "wavPath": "…", "url": "/dsh-fish-service/audio?path=…", "ms": 610, "voice": "dafeiyu", "bytes": 91234, "chars": 200 }
  ],
  "chunks": 1,
  "chars": 180,
  "codeBlocks": 1,
  "codeLines": 4,
  "truncated": false,
  "voice": "dafeiyu",
  "speed": 1,
  "concurrency": 2,
  "cachedChunks": 0,
  "cacheHits": 0
}
```

- 单段也走 `items`；`wavPath` 是 `items[0].wavPath`（兼容任务书里的 `{ok,wavPath,ms}`）；
- `fish.service.tts` 单次最多 20 条，这里最多 40 段，**按 20 条一批**调用；
  批与批之间按 `config.readConcurrency`（默认 2，1~4）有限并发，结果按段序拼接；
  某批失败会降级为串行重试该批，成功后 `degraded:true`；
- 空文本 / 只剩代码块 → `400 bad_request`（hint 说明原因）；
- 语速越界 → `400`；
- 服务侧失败（`service_down` / `vram_exhausted` / `model_missing` / `timeout`）→ `200 {ok:false, code, hint}`，
  前端直接显示 hint，不显示英文堆栈。
- 新增字段 `concurrency` / `cachedChunks` / `cacheHits`（可选 `degraded`）；原有字段语义不变。

> 流式朗读请用 `POST /read/plan` + `POST /read/segment`（见
> [`docs/TTS_CACHE.md` 第 5 节](TTS_CACHE.md#5-流式朗读边合成边播)）；`/read` 保留兼容。

### 5.2 `GET /audio?path=…`

- 只返回 **`config.cacheDir` 里面**的文件（`isPathInside`：`resolve()` 后比较前缀，
  Windows 不区分大小写；**不**接受目录本身、`..`、NUL）；
- 只认 `.wav/.webm/.ogg/.opus/.mp3/.m4a`；扩展名 → `content-type`；
- 不存在 → 404；越界 → 403；扩展名不对 → 400；>128MB → 413；GET only。

### 5.3 `POST /transcribe-upload`

multipart 字段：`file`（或 `audio`）、`durationMs?`、`language?`（auto/zh/en/ja）、`speaker?`。

- 25MB / 5 分钟硬限制；临时文件写 `<cacheDir>/tmp/<uuid>.<ext>`，**请求结束即删**；
- 调 `fish.service.asr(file, {language, speaker, timeoutMs})`；
- 返回 `{ok, text, ms, elapsedMs?, language?, speaker?, speakerError?, bytes}`；
- 缺文件 → 400；超时/服务错 → `200 {ok:false, code, hint}`。

### 5.4 `POST /voice-upload`

multipart 字段：`file`、`durationMs?`。

- 存到 `<cacheDir>/voice/<uuid>.<ext>`（按 TTL/LRU 清理，与其它产物一致）；
- 返回 `{ok, path, name, bytes, mime, durationMs?}`；25MB / 5 分钟限制同上。

> 这两条上传路由在 `/state`、`/save` 之外，**不接触 token**，也不把音频发给 localai 以外的地方。

### 5.5 `POST /read/plan` 与 `POST /read/segment`（流式朗读）

- `/read/plan`：`{text, maxChars?, voice?, speed?, skipCodeBlocks?}` → **立即**返回
  `{ok, segments:[{index,text,chars}], chars, codeBlocks, codeLines, truncated, voice, speed, maxChars}`，**不做 TTS**；
- `/read/segment`：`{index, total?, text, voice?, speed?}` → 单段走 `tts()` →
  `{ok, index, wavPath, url, ms, cached, bytes, voice?, speed?, total?}`；
- `index` 必须 `0~39`；给 `total` 时还要求 `1~40` 且 `index < total`；空文本 / 语速越界 → 400；
- 同一段第二次请求由缓存直接命中（`cached:true, ms:0`）。

时序、完整 schema 与限制见 [`docs/TTS_CACHE.md`](TTS_CACHE.md)。

### 5.6 `GET /cache/stats`、`POST /cache/clear`、`POST /cache/cleanup`

- `/cache/stats` → `{ok, kind:'tts', files, bytes, hits, misses, hitRate}`（服务层内存计数，不扫盘）；
- `/cache/clear {kind?}` → 清缓存并返回 `{ok, kind, files, bytes, kinds}`；
  省略 kind 清 `tts/separate/vision/tmp`，**保留** `voice`；
- `/cache/cleanup` → 调 `cache.cleanup()`，返回 `{ok, expired, lru, bytesFreed, scanned}`；
- 设置页「缓存」卡片展示统计并提供这两个按钮。

## 6. 文本预处理与分段（`lib/speech.js`）

宿主做预处理，规则只有一份，可离线单测。

### 6.1 清洗

| 输入 | 处理 |
| --- | --- |
| 代码围栏 ```` ``` … ``` ````（含未闭合到文末） | 默认**整段删除**；`skipCodeBlocks=false` 时替换成「（代码块，共 N 行）」，**不念代码本身** |
| 4 空格 / Tab 缩进代码块 | 删除 |
| 行内代码 `` `x` `` | 去掉反引号，保留 `x` |
| `**粗**` / `__粗__` / `*斜*` / `_斜_` / `~~删~~` | 去标记留文字 |
| 标题 `### x` / 引用 `> x` / 列表 `- x`、`1. x` / 任务框 `- [ ]` | 去前缀 |
| 表格 | 分隔行（`\|---\|`）删除；单元格用「，」连接 |
| 分割线 `---` / `***` / `___` | 删除 |
| `[文字](url)` / `[文字][1]` | 只读「文字」 |
| `![alt](url)` | 只读 `alt` |
| 裸 URL / `<https://…>` | 删除 |
| HTML 标签 / 注释 | 删除 |
| `[QQ]` / `[/QQ]` | 删除标记，**块内文字保留** |
| HTML 实体 `&nbsp;` `&amp;` `&lt;` `&gt;` | 还原 |

### 6.2 分段（默认 `maxChars = 2000`，可设 200~5000）

1. 先按**空行**切段；
2. 单段超过 `maxChars`：按句末标点（`。！？!?；;…`）切句，贪心合并到不超过 `maxChars`；
3. 单句仍超长：按 `maxChars` 硬切，优先在逗号/顿号/空格处断开；
4. 过短的相邻段合并（`< 60% maxChars` 才尝试），减少 TTS 请求数；
5. 总字数最多 **20000**（超出截断并 `truncated:true`），最多 **40 段**（超出截断并 `truncated:true`）。

> 单段上限与 localai 的 `/tts` 5000 字硬上限是两回事：这里是「朗读体验」的分段，
> 2000 字一段在 IndexTTS 上更稳。

## 7. 设置字段（P2 新增）

| 字段 | 默认 | 范围 | 作用 |
| --- | --- | --- | --- |
| `ttsSpeed` | `1.0` | 0.5~2.0 | 朗读语速 |
| `autoRead` | `false` | bool | 新会话默认自动朗读（未单独设置过的会话沿用） |
| `autoReadSessions` | `{}` | 最多 200 条 | 按会话保存的自动朗读；键须以 `session-` 开头，值转布尔 |
| `readMaxChars` | `2000` | 200~5000 | 朗读单段最大字数 |
| `readConcurrency` | `2` | 1~4 | `/read` 批间并发度（1 = 完全串行） |
| `readSkipCode` | `true` | bool | 朗读时去掉代码块（关=念「代码块，共 N 行」） |
| `recordMime` | `"auto"` | auto/webm/wav | 录音格式 |
| `rememberVoiceChoice` | `true` | bool | 记住上次三选一（只做默认高亮） |
| `asrLanguage` | `"auto"` | auto/zh/en/ja | 语音输入 ASR 语言 |

`fish.service.config.set` 已加入这些字段的白名单与校验；非法值返回 `warnings` 且不写入。

## 9. 重启后真机验收（逐条）

> **不要在这里重启 DSH**；重启由父 agent 执行（见 `tools/restart-p2-verify.ps1`）。
> 验收前建议先停用 `dsh-speak-up`（避免两个朗读入口混淆；本插件不负责改 profile）。

0. 准备：确认 `dsh.profile.bundles` 含 `dsh-fish-service`；DSH 重启后打开任意会话。
1. **设置页**：设置 → 本地 AI，应看到「朗读」「语音输入」两个分区；改语速 1.2、单次字数 1500、点保存；
   刷新页面后值还在。
2. **朗读按钮**：任选一条助手回复，操作行（复制按钮右侧）应只有一个喇叭按钮。
   点一下 → 出现转圈 → 开始播放；再点 → 停止。播放中切到另一条消息点朗读 → 上一条立刻停。
3. **长文本**：让助手回一段 >2000 字（或临时把「单次最大字数」调到 200），点朗读：
   按钮右侧出现 `1/2`、`2/2`；**第 1 段应比原来明显更快出声**（不必等全部合成）；
   段间没有明显空白；中途停止后不再出声。
4. **缓存命中**：同一条消息连点两次朗读（或同文本两个回复）：
   第二次应明显更快；`Network` 里第二次的 `/read/segment` 返回 `cached:true`；
   设置页「缓存」卡片命中次数应 +N、命中率上升。
5. **预处理**：让回复里带代码块、`[QQ]…[/QQ]`、Markdown 链接、表格；朗读时不应念出 `#`、`**`、`[QQ]`、
   链接 URL；代码块不念。关掉「去掉代码块」再读，应听到「代码块，共 N 行」。
6. **语音输入**：点输入框右侧麦克风 → 浏览器要麦克风权限 → 录制 3 秒：
   - 面板显示红点、计时、波形；点「停止并选择」出现三选一；
   - 点「转文字」→ 文字出现在**光标处**（先在其他位置点一下光标再录，确认位置正确），
     面板显示「已转写 N 字（耗时 X ms）」；
   - 再录一次点「保留语音」→ 输入框出现 `（语音附件：C:\Users\…\fish-service-cache\voice\….webm）`，
     文件确实存在；再点「补上文字」→ 转写文字补进输入框；
   - 再录一次点「取消」→ 输入框完全没有变化。
7. **记住上次选择**：用过「保留语音」后，再录一次，三选一里「保留语音」应高亮；但它不会自动执行。
8. **自动朗读**：设置页打开「新会话默认自动朗读」后，新建会话发一条新消息，最终回复应自动朗读；
   在某会话把输入框左侧开关关掉，该会话不再自动读，其它会话与全局默认不受影响；切换会话时开关状态跟随该会话；
   工具调用/思考/代码块不应被念。
9. **服务未启动**：停掉 localai（父 agent 用 `stop_ai_service`/任务计划停止）后点朗读/转文字：
   按钮不白屏、不报 JS 异常，显示中文引导（「本地 AI 服务没在运行…」）。
10. **并发度**：设置页把「朗读并发度」改成 1，保存后读一段长文，应仍然正常（只是更慢）；
    改成 4 也就最多 4 批同时；非法值（0/9）保存时给 warning 且不写入。
11. **无重复入口**：浏览器 Network 里没有 `/dsh-tts-api/*`；页面上只有一个朗读控件。
12. **日志**：`C:\Users\Administrator\.dsh\fish-service.log` 最近 20 行无异常堆栈。

## 10. 已知限制

1. **音频附件降级**：DSH 0.2.2 的草稿附件只接受上传回执 id，插件拿不到公开接口把本地文件变成草稿附件，
   所以「保留语音」把绝对路径以文本插入输入框（任务书允许的降级）。音频文件仍在 `cacheDir/voice`，
   可手动拖进输入框或播放。
2. **自动朗读的时机**：只对「挂载时偏好已加载 + 比该会话首次看到的末轮更新 + 最后一轮」生效；
   打开旧会话不会回读历史。切走期间到达的新回复，回来时若仍是最后一轮会读一次（按 messageId 去重）。
3. **播放跨消息**：切到别的会话不会自动停（只有点朗读/停止才停）；同一页面内全局唯一播放器。
4. **录音格式**：`wav` 走 WebAudio PCM，采样率跟随设备（通常 44.1/48kHz），文件比 webm 大很多；
   部分浏览器在后台标签页会暂停 `setInterval`，计时可能跳变（录音本身不受影响）。
5. **插入位置**：`insertText` 依赖编辑器版本号；录音期间用户改了草稿会导致第一次插入失败，
   插件会退到「当前光标」再试，仍失败才走剪贴板。
6. **音频回放**：`/audio` 每次读整个文件到内存（≤128MB），TTS wav 通常几百 KB；超长朗读会分成多段。
7. **`[QQ]` 标记**：只剥 `[QQ]` / `[/QQ]` 两个记号；`[语音]…[/语音]`、`[图片]` 等其它出站指令不在朗读清洗范围内
   （会按普通文字念出来，必要时后续补规则）。
8. **首段延迟**：已修复。客户端改为 `/read/plan` + `/read/segment` 流式：第 1 段合成完就播，
   同时预取下一段；`/read` 仍保留「全部合成完再返回」的兼容路径（脚本用）。
   边界：最多 2 个 segment 请求在飞，首段仍要等这一段的合成时间（通常 1~3 秒）。
9. **缓存统计按进程**：DSH 重启后 `hits/misses` 归零；磁盘上的音频仍可命中，只是不计历史。
10. **并发同 key 竞态**：极端情况下两段完全相同、同时未命中，会各合成一次、写两个 wav（只影响一次）。
11. **未做**：暂停/继续（只有停止）、播放进度条、后台播放（切标签页）、把朗读结果导出。
