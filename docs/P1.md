# P1 实现说明（fish-service 骨架）

> 对应设计：[`DESIGN.md`](DESIGN.md) 第 8 节；接口：[`CONTRACT.md`](CONTRACT.md) 第 1~5 节。
> 本文件记录 **P1 实际实现**、与契约的差异、遗留项；不改 DESIGN / CONTRACT 的语义。

## 1. 范围

P1 交付的是 **DSH 宿主侧骨架**：

- Cordis 服务 `fish.service`（`ctx.provide('fish.service', api)`，`apiVersion: "1.0"`）；
- 8 个 Agent 工具（始终注册，失败结构化）；
- 宿主路由 `/dsh-fish-service/*`（设置页用）；
- 配置 / 缓存 / 日志 / 后台健康轮询；
- 设置页：状态、地址、超时、默认音色、缓存用量、能力列表、测试连接、日志；
- 8 个离线测试文件 + 本地 mock localai。

**不在 P1**：安装器、内嵌 WebUI、模型管理、消息朗读、语音输入、`dsh-fish-ops`、
`vision` 的 URL 下载与长视频任务编排。

## 3. 审阅时发现并修复的问题

接手时代码未运行过（`node --check` 直接失败），审阅 + 首轮测试发现：

1. **三个文件有带空格的标识符，语法错误，整个插件无法加载**
   - `lib/errors.js`：`const 字节转 GB` → `字节转GB`
   - `lib/client.js`：`const 猜 MIME` → `猜MIME`
   - `lib/service-api.js`：`const 最大上传 MB` → `最大上传MB`
2. **`service-api.js` 直接 `事件.emit('error', …)`，没有监听者时 Node 抛
   `ERR_UNHANDLED_ERROR`**：任何服务错误都会变成未捕获异常，工具层拿不到结构化错误。
   改为只在 `listenerCount('error') > 0` 时发事件（事件是尽力而为）。
3. **`parseCapabilities` 中 `ready` 用逻辑或合并 `/health.model_ready`**：服务端
   `capabilities.tts.ready=false` 时会被 `/health.model_ready=true` 覆盖，误判为可用。
   改成「服务端 `ready` 字段优先，只有缺字段时才用 `/health` 兜底」。
4. **`expandHome('~/x')` 在 Windows 拼出反斜杠 + 正斜杠的混合路径**：改用 `path.join`。
5. **`/logs?lines=0` 被 `|| 200` 当成缺省**：改为显式数字判断，0 钳到 1。
6. **`fish.service.capabilities` 与契约 1.1 不一致**：原实现是 async 方法。改为同步
   getter（返回最近一次探测结果；首次探测前是全部 `service_down` 的空表），另留
   `capabilitiesAsync()` 给内部/测试强制刷新。
7. **`translate` 没有处理空字符串**：契约要求「空字符串原样返回」。现在空串不发给
   服务端，混合批次会保持原顺序回填；全空批次直接返回。
8. **`separate` 只读 `released_models`**：同时兼容契约里的 `released`。
9. **DSH `volatile` 配置引用导致 `apiVersion` / `ttsVoice` / `cacheDir` 变成
   `[object Object]`**：DSH 0.2.2 会把标了 `volatile` 的字段包成 `{get()}` 引用，
   静态 `ConfigStore` 直接读就得到对象字符串。现在 `normalizeConfig` 统一解包
   （识别 `Symbol.for('cosmokit.volatile.write')`），并且 `Config` schema 不再标
   `volatile`——P1 的配置真身是 JSON 文件，设置页走宿主路由，不依赖 DSH 配置热更新。
   这个问题是**安装后真实路由**验证时发现的：当时 `/state` 返回
   `apiVersion="[object Object]"`，能力全部误判 `api_incompatible`。

## 4. 与 CONTRACT 的差异（P1 有意为之）

| 项 | CONTRACT | P1 实际 | 原因 |
| --- | --- | --- | --- |
| 配置字段名 | `defaultVoice` | `ttsVoice` | 与 `fish-message-config.json` 现有字段一致，迁移成本低；P2 可加别名 |
| 配置覆盖面 | 20+ 字段（autoRead、maxCharsPerChunk、mirror…） | P1 只落地服务调用相关字段 + `apiVersion` / `cacheDir` / `enabledCapabilities` / `logLevel` | P1 不做朗读/分块/安装/镜像 |
| 宿主路由 | `/status`、`/config`、`/tts`、`/asr`、`/audio/:id`、`/install/*`、`/models/*`、`/webui`、`/metrics` | 只做 `/health` `/state` `/save` `/test` `/logs` `/voices` | 按 P1 任务清单；其余属 P2/P3 |
| POST 重试 | `timeout` / `upstream_error` 最多重试 1 次 | **POST 不自动重试**；只有幂等 GET 重试 1 次 | 避免 TTS / 分离 / 视觉重复推理；需要在工具层显式重试 |
| `/jobs` 提交 | `enqueue(files)` 先 multipart 上传 | 带 `files` 返回 `not_implemented` | 上传到服务端属 P3 |
| `visionFrames` 长视频 | >10 分钟或 `effort=high` 走 `/jobs/vision` | 全部走同步 `/vision/frames` | P1 不做任务编排 |
| `visionFrames.url` | 先下载再处理 | 返回 `not_implemented` | 下载能力属 P3 |
| `install.*` | 完整安装 API | 只读 `status` / `adopt`，其余 `not_implemented` | P3 |
| `fish.service.capabilities` | 同步 record | 同步 getter（最近快照） | 见上；避免 async 属性 |
| 能力缓存 TTL | 60s（DESIGN 8.2） | 30s（任务要求与测试） | 任务要求 30s |
| `jobs` 可用性 | 服务可达且 `jobs.enabled` | 同上；`jobs` 字段缺失按启用处理 | 兼容旧服务 |

错误码与 HTTP 映射完全按 CONTRACT 第 3 节：连接失败 → `service_down`，507 →
`vram_exhausted`，503（`capabilityReady=false`）→ `model_missing`，503（含“加载/loading”）
→ `model_loading`，503（其它）→ `upstream_error`，504 → `timeout`，
400/401/403/404/409/413/422 → `bad_request`，其它 5xx → `upstream_error`。

### 5.1 真实服务冒烟（手工，不进自动化）

安装后用真实 `localai-service 2.5.0` 做过一次只读冒烟（不加载模型）：

- `health()`：`ok=true`，服务版本 `2.5.0`，`api_version=1`，显存 `6973/8192 MB`；
- 8 个能力全部 `available=true`（模型名/估算显存与 DESIGN 一致）；
- `/voices` 返回 7 个音色（`dafeiyu`、`default`、`female-A` 等）；
- 配置默认值：`baseUrl` / `apiVersion=1` / `ttsVoice=dafeiyu` / `cacheDir` 均正确。

TTS / ASR / 分离 / 视觉的**真实推理**没有在 P1 跑（会加载 1.2~6.4 GB 模型），留给 P1 验收时的
手工冒烟。

## 6. 安装与重启

```powershell
dsh plugin --profile desktop add E:\dsh-fish-service
```

CLI 会把本地目录作为依赖写进 profile，并按安装后的 `dsh.bundle.patch` 自动把
`dsh-fish-service` 追加到 `dsh.profile.bundles`。**不要手改 bundles**；CLI 会在每次
`add` / `update` 后按依赖重算。

安装不会重启 DSH。重启后验证：

```powershell
# 1) profile 里有 bundles
(Get-Content C:\Users\Administrator\.dsh\profiles\desktop\package.json -Raw | ConvertFrom-Json).dsh.profile.bundles

# 2) 宿主路由活着
Invoke-RestMethod http://127.0.0.1:10154/dsh-fish-service/health

# 3) 服务在线时状态页有 capabilities
Invoke-RestMethod http://127.0.0.1:10154/dsh-fish-service/state

# 4) 插件日志
Get-Content C:\Users\Administrator\.dsh\fish-service.log -Tail 50
```

（端口以实际 DSH Web 端口为准；本机当前是 `10154`。）

## 7. 遗留项

- **P2**：消息级朗读 `conversation.chat.assistant-actions`、语音输入
  `conversation.input.right/left`、设置页内嵌 WebUI；`/tts`、`/asr`、`/audio/:id` 路由。
- **P3**：安装/升级/卸载/接管、模型下载与切换、`/install/*`、`/models/*`、日志代理；
  `vision` 的 URL 下载与 `jobs.enqueue(files)` 上传。
- **P4**：`dsh-fish-ops` 与 `fish.message` 最小实现。
- **手工冒烟**：真实 `localai 2.5.0` + 真实模型（TTS/ASR/分离/视觉）尚未在 P1 自动化；
  当前只验证了 HTTP 契约与 mock。
- 设置页尚未做「保存前探测 baseUrl」「音色不存在标红」等体验细节（CONTRACT 1.13 的
  `defaultVoice` 校验、`requiresRestart` 等）。
